## 2. Test suite (23 authored + 2 pre-existing)

- **Correctness / ordering (test10-15):** N=1 sortedness, multi-thread sort, thread-invariance
  across N∈{1,2,4,16,64,100}, value aggregation, multi-emit, one-key-many-values.
- **Edge / state (test20-28):** empty input, single pair, N≫input, N≫keys, all-distinct keys,
  N=1, stage-monotonicity & percentage∈[0,100], reduce-%-by-pairs, isDone-after-wait.
- **Concurrency (test30-36):** concurrent `wait()`, getState hammering, multiple/many
  simultaneous jobs, getOutput-blocks-until-done, destructor-blocks, 10k-pair stress.

All tests are self-validating (exit 0 = pass) and bound any polling loop so a regression
shows up as a clean FAIL/TIMEOUT, never a hang.

- **valgrind memcheck:** CLEAN ×24. 0 bytes lost (definite/indirect/reachable), no invalid
  reads/writes, no uninitialised values. `addOutput` is mutex-guarded; `state_incoder`/`indexer`

- **School oracle (`~os/ex/ex2/run_school_solution`):** our output == reference output,
  byte-for-byte after sort, on both a 5-sentence and a 20-sentence word-count client.

## 4. Helgrind false positives (no action needed)

`run_helgrind.sh` reports "races" on 22/24 tests. **All are false positives.** Helgrind does
not model C++20 `std::barrier`'s internal happens-before, so it flags:
- barrier internals at [MapReduceJob.cpp:49](../MapReduceJob.cpp#L49) / [:62](../MapReduceJob.cpp#L62),
- `mapContexts` read in shuffle ([:56](../MapReduceJob.cpp#L56)) vs map-phase writes (separated by barrier 1),
- `shuffleQueue` read in reduce ([:71-72](../MapReduceJob.cpp#L71-L72)) vs shuffle writes (separated by barrier 2).
The two single-threaded tests (test10, test25) are helgrind-CLEAN, confirming the artifact.
TSan (which *does* model barriers) is clean, which is the authoritative signal.
